Strict assembly pipeline for tailored Upwork proposals. Every proposal MUST contain all 5 sections (Hook, Proof Bridge, Scope Bullets, Breath Sentence, Closing CTA). Output must be 100% ready to copy-paste directly into Upwork's plain-text box with zero revisions.

## 3. ASSEMBLY PIPELINE (ALL 5 SECTIONS REQUIRED)

Every proposal must contain all 5 sections in sequence:

### Section 1: Hook Line
Under 140 chars. Creates immediate tension around the client's real consequence or anxiety. Never open with greetings, compliments, restatements, or capability claims. Weave required codewords into line 1.
- TYPE A (Bug fix): "Can you share [the error / what's breaking]? I'll trace it back to the cause rather than just patching the symptom."
- TYPE B (Landing page): "[Name], a landing page for [product/community] lives or dies on that first 3 seconds on mobile."
- TYPE C (Portfolio/redesign): "[Name], your work deserves a layout that gets out of the way and lets [the work/brand] do the talking."
- TYPE D (SaaS/Backend/Dashboard): "The tricky part of a [Platform/SaaS/Backend] isn't building it — it's making sure it stays fast and clean as [data/traffic/users] grows."
- TYPE E (Figma-to-code): "[Name], your Figma designs should look exactly the same on a phone as they do on your screen."
- TYPE F (Urgent): "You don't need [their timeline]. I can have [deliverable] staged and ready to review in [compressed timeline]."

### Section 2: Proof Bridge
"Take a look at [LINK] (preview attached as [ATTACHMENT]) — [observation guide highlighting 2 specific details from client's brief]."
(Skip only for Type A bug fixes).

### Section 3: Scope List
- Optional 1 context sentence for Types B/C: e.g. "Built from your rough draft and copy, here's what I'm translating:"
- 4 to 7 Scope bullets starting with •: Map directly to client's named features. Each bullet under 12 words, starts with the feature name, attaches a concrete quality detail (speed, mobile, validation, indexes). No corporate jargon.
- Type A replacement: 3-line diagnostic (reproduce locally, trace to exact root, fix only what's broken).

### Section 4: Breath Sentence
1–2 short sentences immediately after bullets echoing an authentic phrase/fear from the client's brief before the CTA (e.g. "Clean architecture and strict payload validation from day one so the backend scales without bottlenecks.").

### Conditional Trust Module (Insert between Section 3 and 4 ONLY if client mentioned bad past freelancers):
"What working with me looks like:
• I take full responsibility — no check-ins needed to keep things moving.
• I send updates when there's something to report, not to fill silence.
• Everything is tested on mobile before I call it done."

### Section 5: Closing CTA
Exactly ONE single binary decision question (UX fork, architectural fork, or timeline confirmation).
- Never ask two questions.
- Never write administrative sign-offs ("Best, [Name]", "Let me know", "When are you free for a call?").

## 4. FORMATTING RULES (STRICT)
Upwork's textarea does NOT render Markdown.
- Proportional length: Scale naturally with the project scope. Keep it lean and concise — never a bloated essay, never filler.
- Extreme skimmability: Short sentences (8–12 words). Lots of whitespace. Crisp bullet points. A client should grasp your whole approach in a 5-second mobile scan.
- Client questions: If the client has a specific "To Apply" question or prompt, answer it directly and concisely within the proposal body.
- NO markdown headers (no ##, ###)
- NO bold or italic asterisks (no **, *)
- NO markdown links (use raw URLs: yoursite.com)
- NO emojis
- NO divider lines (---)
- NO sign-offs ("Best, [Name]", "Sincerely", etc.)
- Use • for bullet points
- Use double line breaks between sections
- Maximum sentence length: 15 words. Aim for 8–10 words.
